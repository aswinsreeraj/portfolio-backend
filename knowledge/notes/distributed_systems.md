# Technical Notes: Distributed Systems Engineering

A collection of foundational patterns and mental models applied in Aswin's systems design:

## 1. The CAP Theorem & PACELC in Practice
- In distributed datastores, network partitions ($P$) are inevitable. Systems must choose between Consistency ($C$) and Availability ($A$).
- For financial wallets (EVNTX) and agent governance budgets (ARDA), Consistency and Partition Tolerance ($CP$) are non-negotiable—preferring failure over writing an invalid or unbacked transaction.
- For search web crawlers (Tenome), high Availability and Eventual Consistency ($AP$) are preferred—an isolated crawler node missing a heartbeat can re-fetch URLs later without blocking the search tier.

## 2. Idempotency & Deduplication Patterns
- Every mutating network call must carry an `Idempotency-Key` header generated by the client (UUID v4).
- The receiving service verifies the key within a database transaction: if already processed, the cached response payload is returned without re-executing side effects; if in-flight, a `409 Conflict` is returned.
- Essential for payment webhooks (Razorpay) and distributed Kafka consumers.

## 3. Distributed Locking & Leases
- Mutual exclusion across multiple nodes requires distributed locks with finite Time-To-Live (TTL) leases.
- Redlock algorithm in Redis: acquire lock on majority nodes, check elapsed time against TTL before proceeding.
- Critical safeguard: always release locks via an atomic Lua script that compares the lock value against the worker's unique owner token to prevent releasing an expired lock held by a subsequent worker.
